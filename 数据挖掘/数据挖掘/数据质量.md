# 数据质量问题的根源

数据挖掘算法经常使用**并非为挖掘目的而收集的数据**（比如企业的交易日志、运营记录、用户行为数据等）。

这些数据在采集时，优先满足的是业务运营（如记账、监控）的需求，而非数据分析的需求，因此会天然存在各种质量问题（如缺失值、错误值、格式不一致、冗余等），给挖掘带来挑战。

# 数据挖掘的质量处理定位

数据挖掘的工作流程中，**数据收集完成后**，需要专门去**检测和修正**这些数据质量问题，而不是假设数据在采集阶段就已经是高质量的。

# 数据挖掘应对质量问题的两个核心方向

1. **数据清洗（Data Cleaning）**
    
    主动识别并修复数据质量问题，比如：
    
    - 填充 / 删除缺失值
    - 纠正错误的数值或格式
    - 去除重复记录
    - 统一不一致的编码（如 “男 / 女” 和 “1/0” 混用）
    
2. **使用容忍低质量数据的算法**
    
    选择或设计**对噪声、缺失、异常值具有鲁棒性**的挖掘算法，这类算法即使在数据存在一定缺陷的情况下，也能输出可靠的分析结果，不需要把数据清洗到 “完美” 状态。

# 数据质量问题的类型
## 噪声
噪声指测量误差中的随即成分，包括数据中的扭曲值和额外的无关对象
### 表现形式
对于对象，表现为多余的 无关的对象
对于属性，噪声表现为原始值的修改或损坏

比如：在质量差的电话上的奇怪人声，以及老式电话的雪花点，马赛克点等
<span style='color:gray'>比如我们本来有一个正弦函数，但是其噪声过多（可能来源于各种阻拦或信息的收集方式不当），我们得到的图像就是一个很混乱的曲线，难以让我们发掘出这是一个正弦函数</span>

同时，噪声在数据具有时间或空间成分时，更加常见
### 影响
噪声会掩盖数据潜在的模式，导致我们更难挖掘出有意义的信息

### 处理方式
我们通常用信号处理和图像处理的方式来减少噪声，来揭示出可能被噪声淹没的信息

噪声消除的工作通常十分困难，所以我们提升算法的鲁棒性，我们采用一些能够处理噪声的算法

## 异常值
指的是和大多数其他数据具有显著不同的特征的值，或其属性值和典型值相比来说不寻常

### 两种异常值的定位
#### 异常值作为噪声
异常值作为干扰的信息出现，阻拦我们发掘数据中的信息

#### 异常值作为研究目标
异常值就是我们在这些数据中寻找的内容，我们研究一个数据就是在探究其会不会出现，出现什么样的异常值
	比如，我们在一大群人的消费记录中，找到短时间内消费异常高的人，这个人一定有值得研究的信息

所以，我们要根据实际情况给异常值找到合适的定位

## 缺失值
就是数据中的null，没有任何数据的地方

### 缺失值的来源
- 信息没有收集到，可能信息提供人不愿提供这方面的信息等，比如调研的时候有些人对自己的年龄保密
- 数据可能不适用于所有情况，比如你想调研的信息里涉及到胡子的位置，那么这个属性天生无法被女生提供
- 系统错误，就是数据被设备搞丢了
- 数据丢失

### 缺失值的处理方案
- 删除含有缺失值的行或列——既然胡子这个属性会有确实，干脆就不统计了
- 估计，填充缺失值——用前后值，数据的中位数或平均数来填充缺失值
- 忽略

处理缺失值的方案取决于你想得到的目标

## 重复数据
彼此相通或几乎相同的数据对象

### 重复数据的来源
- 同一个人 不同的标识符——有呆逼用好几个账号给一个问卷填了好几次，而且内容完全相同
- 合并来自不同来源的数据——有人出现在多个数据库中
- 数据输入错误——不小心被记录了多次
- 智械危机

### 对数据的处理
识别并删除重复的数据就好了

而对于特地重复的数据（多笔相同交易，合法的重复测量，客观的重复如重名等），大多数情况不应该被删除

应该严格根据数据的来源和背景来确认是重复数据还是巧合
